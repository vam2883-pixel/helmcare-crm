## 3. База данных (Supabase)

Таблицы: `machines` (80 строк, реальные HC-001…HC-080), `machine_monthly` (668, реальные),
`wash_stats` (30 дней, реальные агрегаты сети), `franchise_leads` (6, демо),
`technicians`, `campaigns`, `contractors`, `legal_contracts`, `dev_projects`, `clients`,
`notifications`, `content_items`, `machine_logs`, `app_settings` — демо-сиды.

Схема: `supabase/schema.sql` + `supabase/migration-002-monthly.sql`.
RLS: включён на всех таблицах, но политика `open_access for all using(true)` —
**любой, у кого есть publishable-ключ (он в бандле сайта), может читать и писать всё**.

## 4. Реальные данные и их происхождение

- Источник: Excel-выгрузка вендинговой платформы («HelmCare Washes Sales new.xlsx», лист AutomatedSheet, ~13 290 продаж, 2025-02 → 2026-08) + лист «Платные мойки» (52 локации, статусы, промо).
- Импорт: разовый, выполнен вручную (скриптом) 2026-08-19. **Регулярной синхронизации нет** — данные устаревают с каждым днём.
- Привязка «автомат → локация»: из сводной таблицы Google Sheets (в xlsx-экспорт не попадает!). 52 из 80 автоматов имеют локации; 28 — «Локация не указана».
- Статус online/offline: **вычислен по активности продаж** (мойка за последние 7 дней), при импорте скорректирован статусами из листа. Настоящей телеметрии нет.
- Валюта: IDR (Midtrans). Средний чек ~15–19 тыс. Rp; есть Free/Coupon мойки (2 681 + 2 659 шт.) — в текущих цифрах выручки не смешаны (0 Rp), но в счётчике моек учитываются вместе.

## 7. Риски безопасности (по убыванию)

1. **КРИТИЧНО. Открытая запись в БД**: publishable-ключ в бандле + политика `using(true) with check(true)` = кто угодно может изменить/удалить все данные через REST. Лечится: Supabase Auth + настоящие RLS-политики по ролям.
2. **КРИТИЧНО. Демо-авторизация**: пароли в исходнике/бандле, «роль» — состояние в браузере. Любой видит подсказки паролей на странице логина прода.
3. Нет audit log — изменения анонимны и неотслеживаемы.
4. GitHub PAT (истекает 2026-08-26) использовался в командах пуша — после истечения нужен новый механизм (или подключить git credential store).
5. Free-план Supabase: пауза проекта после недели неактивности; 500 МБ лимит.

## 8. Технический долг

- `App.jsx` — 3 369 строк, все 16 секций в одном файле. Работать можно, но каждое изменение рискует задеть соседей. Рекомендация: выносить секции в файлы **по мере доработки** (не большим взрывом).
- Захардкоженные числа в OverviewSection (выручка месяца, алерт AW-003/004, «+8%» тренды без базы сравнения — прямое нарушение §6).
- Смешение демо и реальных данных без маркировки (§62).
- Нет тестов на расчёты (§67).
- Нет URL-роутинга — нельзя дать ссылку на конкретный автомат.
- fallback.js расходится с реальной схемой (AW-xxx, ₽, рубли).

## 9. Ограничения данных (важно для ожиданий)

- **Телеметрии нет** → настоящий uptime, MTTR, proof-of-play для DOOH невозможны, пока нет API вендинговой платформы. Пока: прокси-метрики по продажам, помеченные как ESTIMATED.
- **Идентификации клиентов нет** в выгрузке → клиентская база/ретеншн (§33–34) заблокированы до появления customer id (Midtrans order data / приложение / QR).
- **Расходы** (аренда, зарплаты, себестоимость мойки) в системе отсутствуют → юнит-экономика (§32) будет DATA INCOMPLETE, пока их не внесут. Себестоимость ~Rp 4 000/мойка — задать конфигом.
- **Регулярный импорт продаж** — нужен процесс (ручная загрузка xlsx в UI или интеграция с платформой), иначе все KPI протухают.
